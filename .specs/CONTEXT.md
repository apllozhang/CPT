# CONTEXT — 项目级共享上下文

## 术语表

| 术语 | 定义 |
|------|------|
| **竞品源** | 一个被追踪的竞争对手网站入口，包含名称、URL、采集配置 |
| **采集模板** | 从 AI 自动提取生成的、针对特定网站的采集规则（字段映射 + 选择器/提取策略） |
| **采集快照** | 一次采集任务对某个竞品源的完整结果，包含时间戳、状态、提取的产品数据 |
| **产品参数** | 从竞品页面提取的结构化数据，以 key-value 形式存储，不同产品可有不同字段集 |
| **变更 Diff** | 同一产品在两次不同采集快照之间的参数差异（新增/修改/删除） |
| **分组** | 用户自定义的分类容器，可将竞品源或产品按品类/产品线组织 |
| **AI 提取** | 通过大模型 API 自动识别网页中的产品参数表格并结构化的过程 |

## 已锁决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 视觉调性 | 工业风（3️⃣） | 数据密集型工具，参考 Bloomberg/Grafana |
| 用户模式 | V1 单人本地 | 先跑通核心流程 |
| 采集策略 | 模板优先 + AI 兜底 | 平衡准确率与灵活性 |
| 参数存储 | 动态字段（EAV / JSON） | 不同产品线参数不同，无法固定 schema |
| AI 提取方式 | 调用外部大模型 API | 利用 Claude/OpenAI 理解能力，不在本地部署模型 |

## 默认行为

- 新添加的竞品源默认启用、采集频率默认每天
- 采集模板首次由 AI 自动生成，用户可手动微调
- 定时采集失败不阻断后续任务，记录失败原因继续
- 产品参数表格默认按采集时间倒序排列
- Diff 视图默认对比最近两次快照
