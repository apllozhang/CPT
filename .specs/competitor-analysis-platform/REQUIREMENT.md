# REQUIREMENT: 竞品分析平台 — 自动采集与参数对比系统

- **Change ID**: competitor-analysis-platform
- **关联**: `@.specs/competitor-analysis-platform/CHANGE.md`、`@.specs/CONTEXT.md`

---

## 用户故事

- **US-1**：作为产品经理，我想添加竞品网站 URL 并让系统自动识别和提取产品参数，以便无需手动录入。
- **US-2**：作为产品经理，我想为每个竞品配置定时采集（按小时/按天），以便持续追踪参数变化而不需要每次手动操作。
- **US-3**：作为产品经理，我想手动触发一次即时采集，以便在竞品发布新品时立刻获取最新数据。
- **US-4**：作为产品经理，我想在可排序、可筛选的表格中查看所有竞品的产品参数，以便快速横向对比。
- **US-5**：作为产品经理，我想查看某个产品在不同采集时间点的参数变更（diff），以便发现竞品悄悄改了什么。
- **US-6**：作为产品经理，我想对竞品和产品进行分组/标签管理，以便按产品线或品类组织数据。
- **US-7**：作为产品经理，我想查看采集历史记录（每次采集的状态、时间、结果数量），以便知道系统是否正常工作。

## 验收准则（AC）

### AC-1 · 添加竞品源并首次采集

- **Given** 用户在系统里点击「添加竞品」
- **When** 输入竞品名称（如"H3C WLAN"）和产品页 URL（如 `https://www.h3c.com/cn/.../IP_Wlan/`），点击「保存并采集」
- **Then** 系统通过 AI 自动识别页面中的产品列表，提取产品型号、分类层级（如 AC / 高密型AP / 室外AP）、WiFi 标准（如 Wi-Fi 7 / Wi-Fi 6）、关键参数摘要（如速率、流数、接口），结构化存入数据库，并展示采集结果摘要（发现 X 个产品，提取 Y 条参数）
- **验证方式**: 添加 H3C WLAN 页面 URL，确认至少提取到 10 个产品型号及其分类

### AC-2 · 配置定时采集

- **Given** 至少有一个已添加的竞品源
- **When** 用户在竞品源设置中选择采集频率（每小时 / 每 6 小时 / 每 12 小时 / 每天 / 每周）并启用定时
- **Then** 系统按设定频率自动执行采集，每次采集结果作为独立快照保存，不覆盖历史数据
- **验证方式**: 设置频率为每小时，等待 1 小时后确认产生了新的采集记录

### AC-3 · 手动触发采集

- **Given** 至少有一个已添加的竞品源
- **When** 用户点击竞品源旁边的「立即采集」按钮
- **Then** 系统立即执行一次采集，完成后显示结果摘要（新增/变更/未变产品数量），采集记录出现在历史列表中
- **验证方式**: 手动触发已配置的竞品源，确认产生新的采集记录并展示结果摘要

### AC-4 · 产品参数表格 — 查询与排序

- **Given** 系统中已有采集到的产品数据
- **When** 用户进入「产品对比」页面，选择一个或多个竞品源，选择产品分类（如"高密型AP"）
- **Then** 展示该分类下所有产品的参数表格，支持按任意列排序（型号/速率/流数/WiFi标准/采集时间），支持按关键词搜索筛选
- **验证方式**: 选择 H3C → 高密型AP，确认看到 WA7638/WA7538 等产品，按速率降序排列

### AC-5 · 历史变更 Diff

- **Given** 同一产品至少有 2 次采集记录
- **When** 用户点击某产品的「变更历史」
- **Then** 展示该产品的所有采集时间线，选择任意两次可查看参数 diff：新增字段标绿、修改字段标黄并展示旧值→新值、删除字段标红
- **验证方式**: 对同一竞品执行两次采集，在两次之间若页面有变更，确认 diff 正确高亮

### AC-6 · 分组与标签管理

- **Given** 系统中有多个竞品源和产品
- **When** 用户创建分组（如"无线AP"、"交换机"）并将竞品源或产品归入分组
- **Then** 在产品对比页面可按分组筛选，只看同组内的竞品产品
- **验证方式**: 创建"无线AP"分组，将 H3C WLAN 和另一个竞品的 AP 归入，确认筛选后只显示该分组产品

### AC-7 · 采集历史记录

- **Given** 系统中已有多次采集记录
- **When** 用户进入「采集历史」页面
- **Then** 展示所有采集记录列表（竞品名称 / 采集时间 / 状态：成功/部分失败/失败 / 发现产品数 / 变更数），支持按时间范围筛选，点击可查看详情
- **验证方式**: 手动触发 2-3 次采集后，确认历史列表正确展示所有记录

### AC-8 · 采集规则配置（模板 + AI）

- **Given** 用户添加了一个新的竞品 URL
- **When** 系统首次采集时 AI 自动提取
- **Then** 系统自动生成该站点的「采集模板」（包含 CSS 选择器映射或 AI 提取规则），用户可在「采集配置」页面查看和微调模板（如指定只提取某个 div 区域内的表格），后续采集优先使用模板、AI 作为兜底
- **验证方式**: 添加新 URL 后首次采集完成，确认自动生成了采集模板，修改模板后重新采集确认生效

### AC-9 · 采集失败处理

- **Given** 某次采集中部分页面请求失败或解析异常
- **When** 采集任务完成
- **Then** 在采集记录中标记失败的产品/页面及失败原因（如 HTTP 404 / 超时 / 解析失败），成功部分的数据正常入库，不因部分失败丢弃全部结果
- **验证方式**: 输入一个包含无效链接的竞品源，确认部分成功、部分标记失败原因

## 范围切分

### v1（本次必做）

- 竞品源 CRUD（添加 / 编辑 / 删除 / 启停）
- AI 自动提取 + 模板自动生成 + 模板微调
- 定时采集（按小时/天/周）+ 手动即时采集
- 产品参数结构化存储（支持动态字段，不同产品线参数不同）
- 产品参数表格：查询、排序、关键词筛选
- 历史变更 Diff（新增/修改/删除高亮）
- 分组/标签管理
- 采集历史记录与状态追踪
- 采集失败部分成功处理
- 单人本地使用（无需认证系统，本地运行）

### v2（下一轮考虑）

- 团队多用户 + 权限管理
- 参数变更告警通知（邮件 / Webhook / 站内消息）
- 导出报告（Excel / PDF）
- 趋势图表（参数随时间变化折线图）
- 竞品雷达图 / 综合评分卡
- 登录态爬取（Cookie / Session 管理）
- 采集模板共享市场（用户可导出/导入模板）

### out（永远不做）

- 大规模分布式爬取（百万级页面）
- IP 轮换 / 验证码破解等反爬对抗
- 代理池管理
- 竞品舆情/评论采集（只做产品参数，不做内容）

## 非功能性需求

- **性能**: 单次采集 20 个竞品站点（每站 ≤ 50 个产品页）在 5 分钟内完成；参数表格加载 ≤ 2s（1000 行内）
- **可访问性**: 无特殊要求（内部工具，单人使用）
- **安全**: 本地部署，无需 HTTPS；在 UI 上展示合规使用提示
- **兼容性**: Chrome 最新版即可（内部工具，不兼容旧浏览器）
- **可观测性**: 采集任务日志（成功/失败/耗时）；采集异常时在界面上标红提醒
- **存储**: 单机 SQLite 或 MySQL，预估 20 站点 × 50 产品 × 365 天 ≈ 36 万条快照，单机可承受

## 依赖与假设

- **依赖外部 AI API**: AI 提取功能依赖大模型 API（Claude / OpenAI），需用户自行配置 API Key
- **依赖目标网站可访问性**: 采集前提是目标网站公开可访问、无强反爬
- **假设**: 竞品官网产品页结构相对稳定（不会每天改版），模板 + AI 能覆盖 90%+ 场景
- **假设**: 单人使用，无需并发控制和数据隔离
