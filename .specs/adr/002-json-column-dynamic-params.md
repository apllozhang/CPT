# ADR-002: MySQL JSON 列存储动态产品参数

## Context

不同竞品、不同产品线的参数字段完全不同（如 AP 有"流数/速率/频段"，AC 有"管理AP数/吞吐量"）。需要一种灵活的存储方式。

## Decision

使用 MySQL 8 的 JSON 列存储产品参数，数据格式为 flat key-value `{ "参数名": "参数值" }`。

## Consequences

**优势**：
- 无需预定义 schema，不同产品随意添加参数
- MySQL 8 `JSON_EXTRACT` / `JSON_TABLE` 支持索引查询
- 一条 SQL 能完成筛选排序（如按"速率"排序）
- 与 Drizzle ORM 兼容好（`json()` 列类型）

**代价**：
- JSON 内字段无外键约束，数据一致性靠应用层
- 深度嵌套查询性能不如关系列（V1 参数拍平为一层，不嵌套）
- 无法跨快照 JOIN 查询（需应用层 diff）

**备选方案**：
- EAV 表：查询需多 JOIN，复杂度高
- 独立字段表：每类产品一张表，维护地狱
- MongoDB：引入新数据库组件，与 MySQL 双库增加运维

**推翻条件**：如果参数字段趋于稳定（如都跑同一类产品），可抽取公共列为关系字段 + JSON 列存差异字段。
